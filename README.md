# AudioShare

Два ПК в одной Wi-Fi сети проигрывают один и тот же звук с минимальной задержкой + общий буфер обмена.
Только Windows 10/11 (WASAPI).

## Сборка и запуск

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```
cd AudioShare
dotnet run -c Release
```

Один exe-файл, который можно скопировать на второй ПК (там .NET ставить не нужно):

```
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Файл появится в `bin\Release\net8.0-windows\win-x64\publish\AudioShare.exe`. Его нужно запустить на **обоих** ПК.

## Как пользоваться

1. На главном ПК: выбери «Хост», нажми «Запустить хост». Появится 6-значный код и IP.
2. На втором ПК: выбери «Клиент», нажми «Найти хост» (или впиши IP), введи код, «Подключиться».
3. При первом запуске Windows спросит про брандмауэр. Разреши доступ в **частных сетях** (порты: TCP 48000, UDP 48001 и 48002).

## Режимы звука на хосте

**Не синхронизировать** (по умолчанию). Хост играет звук как обычно, программа лишь копирует его клиенту. У клиента звук приходит на 40–80 мс позже. Подходит, если ПК стоят в разных местах.

**Синхронизировать.** Хост сам задерживает свой звук на время, которое нужно клиенту (половина RTT + буфер клиента + твоя ручная подстройка), и звук играет одновременно на обоих ПК. Windows не умеет задерживать звук приложений, поэтому нужен виртуальный кабель:

1. Установи бесплатный [VB-CABLE](https://vb-audio.com/Cable/).
2. В Windows на хосте выбери устройство вывода по умолчанию **CABLE Input** (или назначь его нужным приложениям в «Параметры → Звук → Микшер громкости»).
3. В AudioShare: «Звук какого устройства транслировать» = **CABLE Input**, «Играть звук на хосте через» = твои реальные колонки или наушники.
4. Включи режим «Синхронизировать» и запусти хост.
5. Если слышно эхо или звук хоста опережает клиента, двигай ползунок «Подстройка задержки». Подбирается один раз на ухо; плюс — клиент позже, минус — раньше.

Если захват и вывод указать одним и тем же устройством, программа отключит локальный звук, иначе получится петля.

## Задержка

Складывается из: захват (около 10 мс) + сеть по Wi-Fi (2–10 мс) + буфер клиента + буфер вывода WASAPI (около 20 мс). Реалистично получается 50–90 мс при буфере 40 мс. Если на 5 ГГц Wi-Fi звук идёт ровно, уменьшай буфер на клиенте до 20–30 мс; если появились щелчки, увеличивай. Для снижения задержки подключай хотя бы один ПК по кабелю, а на Wi-Fi-адаптере отключи энергосбережение.

## Буфер обмена

Работает текст и картинки в обе стороны, пока включена галочка. Содержимое шифруется (AES-GCM, ключ получается из кода подключения). Файлы пока не передаются.

## Ограничения

- Подключается один клиент за раз.
- Звук по UDP не шифруется (он идёт по локальной сети). Код подключения защищает от подключения чужих устройств и от чтения буфера обмена.
- Режим WASAPI exclusive не реализован.

## Файлы

- `Net.cs`: протокол, шифрование, поиск хоста, управляющее соединение с пингом
- `Audio.cs`: захват (loopback), Opus, джиттер-буфер, вывод
- `HostService.cs` / `ClientService.cs`: логика хоста и клиента
- `ClipboardSync.cs`: буфер обмена и сохранение настроек
- `MainForm.cs`: окно
